# `receipts` CLI (P4.T5 / P4.T6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `receipts ingest|process|export|eval|calibrate|merchants|reprocess|users`, the operator-facing half of a system that so far only speaks HTTP — finishing Phase 4.

**Architecture:** One `argparse` module, `src/receipts/cli.py`, exposed as a console script and as `python -m receipts.cli`. Every subcommand is a function taking parsed arguments plus injected collaborators (`session_factory`, `storage`, `client_factory`, `settings`), so tests call them directly with a fake client and a SQLite session factory instead of shelling out. `main(argv) -> int` returns an exit code rather than calling `sys.exit`. The commands are thin: all the machinery — ingest, `process_receipt`/`process_batch`, the RQ worker, `export_workbook`, `run_baseline`, `calibration_curve`, the repository, the user store — already exists and is merged.

**Tech Stack:** Python 3.11+ (dev interpreter 3.14.4), stdlib `argparse` (no new dependency), SQLAlchemy 2.0, openpyxl, RQ/Redis (optional, `worker` extra), pytest, ruff.

**Source design:** `docs/superpowers/specs/2026-07-29-cli-design.md`. **Contract:** `docs/adr/0013-cli-contract.md` — read it before Task 3.

**Base:** `master @ 77609cb`, 644 tests passing, ruff clean. **Work on a feature branch off master:** `git checkout -b feat/cli`.

## Global Constraints

Project invariants. A violation is a defect, not a style question.

- **`Decimal` on the money path, never `float`** (ADR-0001). A structural test walks the schema and fails on any `Float` column.
- **Prefer `null` over a confident wrong value.** Never invent a number, a URL, or a threshold to fill a gap.
- **Nothing is silently dropped** — every receipt reaches a terminal state (ADR-0011).
- **A machine run never overwrites a `reviewed` row** (ADR-0012). No CLI flag may change this.
- A full PAN is never persisted — last four only; `redact_pan` is never bypassed (ADR-0007).
- Repository conventions (ADR-0006): explicit `Session` first, **the caller commits** (`apply_corrections` owns its own transaction), `ValueError` at the boundary — never a bare `IntegrityError`.
- **`python -m pytest` stays offline**: SQLite, temp-dir `LocalStorage`, fake client, fake queue. No Redis, no network, no provider.
- `python -m ruff check .` clean, line length 100.
- **No interactive prompts anywhere in the CLI** (ADR-0013) — it must run from a script and from CI. Passwords come from stdin, never `argv`.
- **Exit codes:** `0` the command completed; `1` it could not; `2` usage (argparse's own). **A receipt routed to review does not change the exit code** — review is the system working.
- Conventional commit messages (`feat(cli): …`).
- **Never stage `.kiro/settings/mcp.json`**, and leave the untracked `scripts/`, `smoke_*` paths alone — they are the user's own work.
- Alembic's console script is not on PATH — use `python -m alembic`. PowerShell clips piped output; capture with `| Select-Object -Last 3` or redirect to a file.

**Why Task 1 exists — a gap the design did not catch.** `serializers.py` imports `sign_url` from `auth.py`, and `auth.py` imports `fastapi` and `starlette`. `tests/test_import_isolation.py`:

```python
"""The export path must not drag FastAPI in.

``receipts export`` builds a workbook from ORM rows. It has no business
requiring the web framework, and a machine that only runs the CLI should not
need the ``api`` extra installed. This is enforced in a subprocess because the
rest of the suite imports FastAPI freely -- once it is in ``sys.modules`` an
in-process assertion proves nothing.
"""

from __future__ import annotations

import subprocess
import sys


def _imports_cleanly(module: str, forbidden: str) -> subprocess.CompletedProcess[str]:
    code = (
        f"import {module}, sys; "
        f"assert '{forbidden}' not in sys.modules, "
        f"'{module} pulled in {forbidden}'"
    )
    return subprocess.run(
        [sys.executable, "-c", code], capture_output=True, text=True, timeout=120
    )


def test_serializers_import_without_fastapi():
    result = _imports_cleanly("receipts.review.serializers", "fastapi")
    assert result.returncode == 0, result.stderr


def test_signing_imports_without_fastapi():
    result = _imports_cleanly("receipts.review.signing", "fastapi")
    assert result.returncode == 0, result.stderr
```

`src/receipts/cli.py`. Module docstring states the contract from ADR-0013: exit `0` completed / `1` could not / `2` usage; a receipt routed to review is not a failure; no interactive prompts.

```python
EXIT_OK = 0
EXIT_FAILED = 1


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="receipts", description=__doc__)
    sub = parser.add_subparsers(dest="command", required=True)
    _add_ingest(sub)
    _add_users(sub)
    return parser


def main(argv: list[str] | None = None) -> int:
    """Parse ``argv`` and run the command, returning its exit code.

    Returns rather than raising ``SystemExit`` so a test can assert on the
    code; the console-script wrapper below is what exits.
    """
    args = build_parser().parse_args(argv)
    settings = get_settings()
    session_factory = make_session_factory()

    if args.command == "ingest":
        return cmd_ingest(args, session_factory=session_factory,
                          storage=_make_storage(settings), settings=settings)
    if args.command == "users":
        return cmd_users(args, session_factory=session_factory)
    raise AssertionError(f"unhandled command {args.command!r}")  # unreachable: subparsers are required


def _console_main() -> None:  # pragma: no cover - entry point wrapper
    raise SystemExit(main())
```

Later tasks extend that dispatch with one branch each. Build the storage backend
lazily inside the branch that needs it, so `receipts users list` does not fail on
a machine with no blob store configured.

**File size.** With eight commands this module will approach the point where it is
doing too much. If it passes ~500 lines, split the command bodies into
`src/receipts/cli_commands.py` and leave `cli.py` holding the parser and
`main` — do not let it grow past that unexamined.

Add one `_add_<command>(sub)` helper per command so the parser stays readable as commands land in later tasks.

`_make_storage(settings)` returns `LocalStorage(Path(settings.storage_root))` for `storage_backend == "local"` and `S3Storage(settings.s3_bucket)` otherwise, raising `ValueError` when `s3_bucket` is unset.

- [ ] **Step 4: Implement `ingest`**

`receipts ingest <path> [--source upload] [--recursive]`. Collect files (a single file, or a directory's entries — `--recursive` uses `rglob`). For each: `ingest_file(path, storage, source=args.source, max_mb=settings.max_upload_mb)` inside `try/except ValueError`, printing `<receipt_id>  <name>` on success and `REJECTED  <name>: <reason>` on failure. Then, in one session, `create_pending_receipt` per successful job and commit.

Return `EXIT_OK` when every file landed, `EXIT_FAILED` when any was rejected — the summary line reports both counts either way. **Ingest does not enqueue** (ADR-0013): `receipts process` drains the pending rows, so there is one work list.

- [ ] **Step 5: Implement `users`**

`receipts users add <username> [--role reviewer] | list | deactivate <username> | set-role <username> <role>`. Every `ValueError` from the user store becomes a printed message and `EXIT_FAILED`. `list` prints username, role, active flag. The caller commits.

`add` reads the password with `getpass.getpass` — **never `argv`**, which lands in
shell history and in `ps`. This does not violate ADR-0013's no-interactive-prompts
rule: `getpass` reads stdin when stdin is not a tty, so `echo "$PW" | receipts
users add alice` works unattended in a script or in CI. Say so in the command's
help text, because an operator who assumes it needs a terminal will reach for a
flag that deliberately does not exist.
