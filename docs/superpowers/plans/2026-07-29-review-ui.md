# Review UI (P5.T0 + P5.T1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the keyboard-first review screen a human uses to correct a flagged receipt, on a React + Vite frontend served same-origin by the existing FastAPI app.

**Architecture:** A React 19 + Vite + TypeScript SPA in `frontend/`, served under `/app` by a guarded `StaticFiles` mount registered at the end of `create_app` after every API route. Dev goes through a Vite proxy so the browser is same-origin in both dev and prod, which is what makes the existing `same_site="lax"` session cookie work without any `CORSMiddleware`. The screen drives five existing endpoints and changes no API contract.

**Tech Stack:** React 19, Vite, TypeScript, Vitest + @testing-library/react, Playwright. Backend: Starlette `StaticFiles` (already present via the `api` extra — no new Python dependency).

**Design doc:** `docs/superpowers/specs/2026-07-29-review-ui-design.md` (commit `930dadb`). Read it before Task 1.

**Base:** `master @ 930dadb` — 717 tests passing, ruff clean.

## Global Constraints

Every task's requirements implicitly include this section.

- **ADR-0001 — money is a string end to end.** Never `float`, never `Number()`. `<input type="number">` is **banned** on money fields; use `type="text" inputMode="decimal"`. Money, `confidence`, and every `penalty` share one branded `Money = string` type with no arithmetic defined on it.
- **ADR-0014 — no module-top import of an optional extra on any path reachable from an entry point.** The static mount must be **skipped when `frontend/dist` is absent**, or `create_app` breaks for a base install and for CI.
- **The correctable field set is closed.** 17 receipt paths + 7 line-item fields, defined by `_RECEIPT_FIELDS` / `_LINE_ITEM_FIELDS` in `src/receipts/persist/repository.py`. An unlisted path is a `ValueError`. **`line_items[].position` is read-only. No adding or removing line items.**
- **The submit chain `PATCH → complete → next` is strictly sequential and never advances past a failure.**
- **No `catch` may end in a no-op or a console log.** Every failure path terminates in something the reviewer can see.
- **`python -m pytest` stays offline and Node-free.** It must pass on a machine with no `npm`. The frontend adds zero Python test dependencies.
- **Lint:** `python -m ruff check .` (bare `ruff` is **not** on PATH on the dev machine). Line length 100.
- **Every new test must be proven to fail with its fix reverted.** Run the test against the unfixed code and paste the failure before implementing.
- **Verify signatures in the code, never from this plan's snippets.** The prose here is reliable; snippets against existing APIs are the part that has historically been wrong. Read the real function before you call it.
- **Stage only your own task's files. NEVER stage `.kiro/settings/mcp.json`** (a persistent local working-tree edit).
- Conventional commit messages (`feat(scope): …`, `test(scope): …`, `chore: …`).

```python
class _SpaFiles(StaticFiles):
    """``StaticFiles`` that falls back to ``index.html`` for unknown paths.

    The SPA owns its own routing under ``/app``: a hard refresh on
    ``/app/review``, or a bookmarked link to it, must return the shell rather
    than a 404. Only a 404 is swallowed -- a 405 or a permission error is a
    real failure and still propagates to the app's error handlers.
    """

    async def get_response(self, path: str, scope):
        try:
            return await super().get_response(path, scope)
        except StarletteHTTPException as exc:
            if exc.status_code != 404:
                raise
            return await super().get_response("index.html", scope)


def _install_spa(app: FastAPI, settings: Settings) -> None:
    """Serve the built review UI under ``/app``, when it has been built.

    Registered **last**, after every API route, so route ordering cannot
    shadow the API: ``/health`` stays the API's JSON and ``/review/next``
    stays an API route rather than a page. ``/app`` is a prefix the API does
    not use, which is why the SPA lives there instead of at the root -- the
    alternative was moving the API under ``/api``, which would break every
    existing test and the contract ADR-0012 documents.

    Absent directory -> no mount at all (see ``Settings.frontend_dist``).
    """
    dist = Path(settings.frontend_dist)
    if not dist.is_dir():
        return
    app.mount("/app", _SpaFiles(directory=dist, html=True), name="spa")
```

Then in `create_app`, between `_install_write_routes(app)` and `return app`:

`frontend/src/api/client.ts`:

```ts
export class ApiError extends Error {
  constructor(
    readonly status: number,
    message: string,
  ) {
    super(message)
    this.name = 'ApiError'
  }
}

let unauthorizedHandler: () => void = () => {}

/** Register what happens on a 401 (in the app: redirect to /app/login). */
export function onUnauthorized(handler: () => void): void {
  unauthorizedHandler = handler
}

async function errorMessage(response: Response): Promise<string> {
  // Every API failure uses {"error": {"message": ...}}, but a proxy or a
  // crashed worker can still return HTML -- so a body that will not parse
  // must degrade to a usable message rather than throwing a second error
  // that hides the first.
  try {
    const body = (await response.json()) as { error?: { message?: string } }
    return body?.error?.message ?? `request failed (${response.status})`
  } catch {
    return `request failed (${response.status})`
  }
}

export async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const response = await fetch(path, {
    ...init,
    credentials: 'same-origin',
    headers: { 'Content-Type': 'application/json', ...(init?.headers ?? {}) },
  })
  if (response.status === 401) {
    unauthorizedHandler()
    throw new ApiError(401, await errorMessage(response))
  }
  if (!response.ok) {
    throw new ApiError(response.status, await errorMessage(response))
  }
  return (await response.json()) as T
}
```

import { useState, type FormEvent } from 'react'
import { ApiError, request } from '../api/client'

export function LoginPage({ onSignedIn }: { onSignedIn: () => void }) {
  const [username, setUsername] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)
  const [busy, setBusy] = useState(false)

  async function submit(event: FormEvent) {
    event.preventDefault()
    setBusy(true)
    setError(null)
    try {
      await request('/auth/login', {
        method: 'POST',
        body: JSON.stringify({ username, password }),
      })
      onSignedIn()
    } catch (caught) {
      // Never silent: the reviewer must see why they are still on this page.
      setError(caught instanceof ApiError ? caught.message : 'could not sign in')
    } finally {
      setBusy(false)
    }
  }

  return (
    <form onSubmit={submit}>
      <h1>Sign in</h1>
      <label>
        Username
        <input value={username} onChange={(e) => setUsername(e.target.value)} autoFocus />
      </label>
      <label>
        Password
        <input
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
        />
      </label>
      {error !== null && <p role="alert">{error}</p>}
      <button type="submit" disabled={busy}>
        Sign in
      </button>
    </form>
  )
}

import { useEffect, useState } from 'react'

/** The signed URL expires after image_url_ttl_s (default 300s), which a
 *  reviewer can outlive on a single receipt. One silent re-fetch on error
 *  covers that; a second failure is shown rather than leaving a blank pane.
 */
export function ImagePane({
  receiptId,
  fetchUrl,
}: {
  receiptId: string
  fetchUrl: (id: string) => Promise<string>
}) {
  const [url, setUrl] = useState<string | null>(null)
  const [retried, setRetried] = useState(false)
  const [failed, setFailed] = useState(false)
  const [zoom, setZoom] = useState(1)
  const [rotation, setRotation] = useState(0)

  useEffect(() => {
    let live = true
    fetchUrl(receiptId).then((u) => live && setUrl(u))
    return () => {
      live = false
    }
  }, [receiptId, fetchUrl])

  async function handleError() {
    if (retried) {
      setFailed(true)
      return
    }
    setRetried(true)
    setUrl(await fetchUrl(receiptId))
  }

  if (failed) {
    return <p role="alert">Could not load the receipt image.</p>
  }
  return (
    <div>
      <div>
        <button onClick={() => setZoom((z) => z * 1.25)}>Zoom in</button>
        <button onClick={() => setZoom((z) => z / 1.25)}>Zoom out</button>
        <button onClick={() => setRotation((r) => (r + 90) % 360)}>Rotate</button>
      </div>
      {url !== null && (
        <img
          src={url}
          alt="Receipt"
          onError={handleError}
          style={{ transform: `scale(${zoom}) rotate(${rotation}deg)` }}
        />
      )}
    </div>
  )
}

```ts
/** A flat map of dotted correction paths to their string values.
 *
 *  Dotted rather than nested on purpose: CorrectionPatch allows extra keys at
 *  every level and apply_corrections flattens whatever it receives, so a flat
 *  object speaks the server's own path grammar with no structure to build.
 */
export type FieldMap = Record<string, string | null>

/** Only what changed. The server distinguishes "never mentioned" from
 *  "explicitly null" via exclude_unset, so an untouched field must be absent
 *  rather than sent as its current value. */
export function buildPatch(original: FieldMap, edited: FieldMap): FieldMap {
  const patch: FieldMap = {}
  for (const [path, value] of Object.entries(edited)) {
    if (original[path] !== value) {
      patch[path] = value
    }
  }
  return patch
}
```

```ts
import type { FieldMap } from '../review/patch'

/** Which step of PATCH -> complete failed. The distinction is the whole point:
 *  a failed patch wrote nothing and can be retried as-is, while a failed
 *  complete means the receipt is already `reviewed` with its task still open,
 *  so the screen must not advance and must offer to close it alone.
 */
export class SubmitError extends Error {
  constructor(
    readonly step: 'patch' | 'complete',
    readonly cause: unknown,
  ) {
    super(`review submit failed at ${step}`)
    this.name = 'SubmitError'
  }
}

export function patchReceipt(id: string, patch: FieldMap): Promise<unknown> {
  return request(`/receipts/${id}`, { method: 'PATCH', body: JSON.stringify(patch) })
}

export function completeTask(taskId: string): Promise<unknown> {
  return request(`/review/${taskId}/complete`, { method: 'POST' })
}

/** Strictly sequential. Nothing advances past a step that failed.
 *
 *  Re-running this after a network timeout is safe: apply_corrections writes
 *  no corrections row for a path whose stored value already matches, so a
 *  duplicated patch cannot duplicate the audit trail.
 */
export async function submitReview(
  receiptId: string,
  taskId: string,
  patch: FieldMap,
): Promise<void> {
  try {
    await patchReceipt(receiptId, patch)
  } catch (caught) {
    throw new SubmitError('patch', caught)
  }
  try {
    await completeTask(taskId)
  } catch (caught) {
    throw new SubmitError('complete', caught)
  }
}
```

                  }
                />
              </td>

                <MoneyInput

            </tr>
          )
        })}
      </tbody>
    </table>
  )
}

- [ ] **Step 10: Wire editing and approval into ReviewScreen**

Extend `ReviewScreen` with a `fields` state seeded from the loaded receipt, a `dirty` copy, the two components above, and the keyboard handler. The approve handler:

```tsx
  async function approve() {
    if (task === null || receipt === null) return
    setBusy(true)
    setError(null)
    try {
      await submitReview(receipt.id, task.id, buildPatch(original, fields))
      setPendingComplete(null)
      await loadNext()
    } catch (caught) {
      const submit = caught as SubmitError
      const message = submit.cause instanceof ApiError ? submit.cause.message : 'submit failed'
      if (submit.step === 'complete') {
        // The receipt is already `reviewed` but its task is still open.
        // Advancing here would orphan a queue entry silently.
        setPendingComplete(task.id)
        setError(`Saved, but the task is still open: ${message}`)
      } else {
        // Nothing was written -- keep the edits so they can be retried.
        setError(message)
      }
    } finally {
      setBusy(false)
    }
  }
```

Keyboard: ⌘/Ctrl+Enter approves, plain Enter moves focus on. Tab order stays native — do not intercept it.

```tsx
  useEffect(() => {
    function onKeyDown(event: KeyboardEvent) {
      if (event.key === 'Enter' && (event.metaKey || event.ctrlKey)) {
        event.preventDefault()
        void approve()
      }
    }
    window.addEventListener('keydown', onKeyDown)
    return () => window.removeEventListener('keydown', onKeyDown)
  })
```

Render an `Approve (⌘↵)` button carrying the same handler, and — when `pendingComplete` is set — a `Close task` button calling `completeTask` alone.
